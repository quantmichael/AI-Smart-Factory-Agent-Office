# AI Smart Factory Agent Office — 팀원별 역할 및 업무분장

**문서 목적:** 5인 팀의 담당 영역, 협업 경계, 검토 책임을 명확히 한다.

**역할 표기:** 팀원 A~E의 이름은 2026년 10월 16일 제공받은 역할 대응에 따른다. 담당 범위는 이 문서의 역할별 분류이며, 이미 수행한 개인별 기여를 증명하는 기록은 아니다.

**참고 문서:** `docs/plan/09_TEAM_ROLES.md`의 Role A~E, 공통 학습·Cross Review·기여 기록 원칙

## 1. 5인 역할 배정

| 담당 | 역할 | 최종 책임 범위 | 주요 산출물 | 검토자 |
|---|---|---|---|---|
| 팀원 A | 프로젝트 총괄·시스템 통합 | 전체 아키텍처, 모듈 간 인터페이스, Backend API 연결, 통합 일정, 배포·릴리스 점검 | 아키텍처 및 API 계약, 통합 빌드, 배포 절차, E2E 점검 결과 | 팀원 E |

| 팀원 C | 기술문서·RAG | 문서 출처 관리, 파싱·청킹·색인, 검색 품질, 근거·인용 검증 | 문서 목록, 검색 파이프라인, `EvidenceObject` 명세, 검색 평가 기록 | 팀원 B |

팀원 A는 통합과 배포의 최종 책임자이고, 팀원 E는 UI와 검증의 최종 책임자다. 두 역할이 같은 E2E 경로를 다루더라도 코드 통합·릴리스 결정과 사용자 관점의 검증을 구분한다.

## 2. 역할별 실행 업무와 완료 기준

### 팀원 A · 이승훈 — 프로젝트 총괄·시스템 통합

- 공통 데이터 계약과 API 요청·응답 형식을 정리하고 변경을 조정한다.
- ML → API → LangGraph → RAG → 이벤트 → UI → 보고서 흐름을 연결한다.
- 환경 설정, 배포, 복구 절차와 통합 위험을 관리한다.
- **완료 기준:** 통합된 주요 시나리오가 실행되고, 연결 실패와 배포 절차가 문서화되어 팀원이 재현할 수 있다.

### 팀원 B · 남병광 — 데이터·ML 분석

- 저장된 Paderborn Measurement의 입력·전처리·특징 추출을 재현 가능하게 관리한다.
- 데이터 누수를 피하도록 분리 기준과 평가 범위를 기록하고 모델 결과를 `AnalysisResult`로 제공한다.
- 모델의 한계와 신뢰도 해석 범위를 명시한다.
- **완료 기준:** 동일 데이터와 설정으로 추론·평가를 재현할 수 있고, LangGraph에서 결과를 소비한다.

### 팀원 C · 김보미 — 기술문서·RAG

- 기술문서의 출처, 버전, 메타데이터와 색인 범위를 관리한다.
- 검색 결과의 문서·페이지·인용 정보를 `EvidenceObject`로 제공한다.
- 관련 없는 문서 검색과 근거 없는 생성 사례를 평가·수정한다.
- **완료 기준:** 대표 질문에서 검색 근거를 원문까지 추적할 수 있고, 근거가 부족할 때 이를 명시한다.

### 팀원 D · 이혜경 — LangGraph 진단 워크플로

- `AgentState`, 노드, 조건 분기 및 도구 호출을 관리한다.
- 이상 결과, 문서 근거, 사람 검토(HITL)를 연결해 진단·점검 계획·보고서를 생성한다.
- 실행 이벤트와 중단·재개 동작을 UI 및 API 계약에 맞춘다.
- **완료 기준:** 정상·이상·사람 검토·오류 경로를 검증하고 보고서에 입력과 근거의 연결이 남는다.

### 팀원 E · 김시율 — Agent Office UI·품질 검증

- Measurement 선택부터 결과·근거·사람 검토·이력 조회까지 사용자 흐름을 구현한다.
- Backend 이벤트를 화면의 역할별 상태와 진행 기록에 연결한다. 화면의 5개 역할은 독립 LLM 5개를 뜻하지 않도록 설명한다.
- E2E 시험, 사용자 피드백 수집·분석, 개선 재확인과 시연 시나리오를 담당한다.
- **완료 기준:** 사용자가 주요 과업을 수행할 수 있고, 실패·대기·완료 상태와 검증 결과가 기록된다.

## 3. 공동 책임과 검토 방식

1. 모든 팀원은 전체 서비스 흐름을 이해하고, 자신의 모듈이 받는 입력과 내보내는 출력을 설명한다.
2. 각 모듈은 표의 **담당 1명 + 검토자 1명**이 설계·구현·시험 결과를 확인한다. 담당자는 최종 책임자이며 검토자는 대체 구현자가 아니다.
3. 인터페이스 변경은 영향을 받는 담당자와 통합 담당자 A에게 먼저 공유한다. 공통 계약은 `AnalysisResult`, `EvidenceObject`, `AgentState`, `AgentEvent`, `FinalReport`, API 계약을 기준으로 관리한다.
4. 작업 완료에는 구현, 재현 가능한 시험, 문서 갱신, 연결 확인을 포함한다. 실제 검증하지 않은 항목은 완료로 표시하지 않는다.
5. 개인별 실제 기여는 PR·커밋, 설계 결정, 시험 기록, 교차 검토 내역으로 따로 남긴다. 이 문서의 역할 배정만으로 수행 사실을 주장하지 않는다.

Git 커밋은 프로젝트의 통합 반영 이력으로 정리하고, 역할별 관련 소스·문서·시험 결과는 7절의 분류표에서 확인할 수 있다. 팀원별 이름과 역할의 대응은 5절에 기록했다.

팀원별 기여 내용은 담당 기간, 수행 작업, 산출물 경로와 커밋·PR, 검토·시험 기록을 함께 제시해 역할별 작업 흐름을 보여준다. 관련 Discord 대화는 작업 요청·설계 결정·검토·완료 보고의 날짜와 맥락에 연결해 협업 과정을 보강한다. 공개 캡처에는 평가에 필요한 내용만 담고 개인정보를 보호한다.

팀원이 직접 확인한 수행 내용은 작성일을 표시한 **팀원 확인 기록**으로 정리한다. 이름·역할 대응표와 수행 내역은 공통 역할 영역과 산출물 경로로 연결한다. 이 문서는 `/docs/*.md` Git 제외 설정과 별도로 제출 저장소에 포함하고, 관련 이미지의 공개 범위를 점검한다.

## 8. 팀 협업 증빙자료

팀의 업무 협업을 보여주는 자료로 Discord의 업무 관련 대화, PBL 이용 내역, 회의 사진 등을 활용한다. 자료를 모아 제시할 위치로 [팀 협업 증빙자료 폴더](team_collaboration/)를 마련했다.

이 자료는 팀의 업무 논의와 회의 과정을 확인할 수 있는 근거로 제시한다.
