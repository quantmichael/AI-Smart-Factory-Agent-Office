# AI Smart Factory Agent Office
## 사용자 피드백 기록

### 1. 사용자 테스트 개요

이 테스트는 사용자의 관점에서 진단 과정의 이해도, 결과·판정 근거·점검 정보의 접근성, 모바일·PC 화면 사용성 및 업무 활용 가능성을 확인하기 위해 실시했다. 대상은 저장된 Paderborn 베어링 측정 데이터를 선택해 ML 판정, 근거 검색, 점검 권고, 보고서와 이력을 제공하는 AI Smart Factory Agent Office MVP다. 저장 데이터의 화면 재생은 실시간 현장 센서 수집이 아니며, 시스템은 설비를 자동 제어하지 않는다.

| 항목 | 내용 |
| --- | --- |
| 수집 방식·기간 | Google Forms 응답 시트, 2026년 10월 8일~12일(원본 타임스탬프 기준; 시간대 표기는 원본에 없음) |
| 유효 응답 | Google Forms의 익명 유효 응답 **6건**(빈 서식 행 제외). 문항별 수치는 응답 건수를 기준으로 집계함 |
| 고유 참여자 수 | 확인 불가. 이름·연락처 등 식별정보를 수집하지 않아 응답 중복 여부와 서로 다른 참여자가 5명 이상인지 확인할 수 없음 |
| 응답자의 담당 업무 | 연구개발 4건/6건(66.7%), 생산기술 1건/6건(16.7%), 설비 운영·정비 1건/6건(16.7%) |
| 경력·스마트기기 사용 | 3년 미만 1건, 3~10년 3건, 10년 이상 2건; 사용 익숙함 3건, 보통 3건 |
| 평가 내용 | 모바일 7개·PC/노트북 7개 과업의 자가 보고, 5점 동의 척도 6문항, 전체 만족도 5점 척도, 재사용·추천 의향, 주관식 3문항 |
| 분석 방법 | 응답별 선택값을 빈도·비율로 집계하고, 5점 문항은 산술평균을 계산했다. 주관식은 응답 단위로 주제를 분류해 코드 변경과 대조했다. |

수치의 1차 근거는 `feedback/original/`의 Google Forms 응답 시트 `Form Responses 1.html`이다. 같은 폴더의 `분석.html`과 통합 PDF는 집계 교차 확인에만 사용했다. Apps Script의 수동 테스트용 샘플 생성 코드는 설문 응답으로 집계하지 않았다. 원본 파일은 수정하거나 제출 문서에 공개하지 않는다.

**응답 6건**은 설문 제출 건수이며 **참여자 6명**을 뜻하지 않는다. 고유 참여자 5명 이상 여부는 확인할 수 없지만, 익명 설문 응답 6건이 수집·분석된 사실과는 구분한다.

### 2. 사용자 테스트 수행 내용

설문은 모바일과 PC/노트북 각각에 대해 동일한 7개 과업의 결과를 물었다. 과업은 ① 정상/손상 측정 샘플 선택과 진단 시작, ② Agent Office의 진행 상태 확인, ③ 정상/이상 판정 확인, ④ 판정 근거 확인, ⑤ 점검 계획 확인, ⑥ 과거 설비 이력 확인, ⑦ 최종 보고서 확인이다. 각 선택지의 ‘완료·부분완료·미완료’는 **응답자의 자가 보고**이며, 관찰자가 측정한 기능 테스트 성공 여부나 수행 시간은 아니다.

### 4. 정성적 피드백 분석

R01~R06은 응답 시트의 시간순 익명 식별자다. 아래는 원문을 주제별로 **요약**한 것으로, 따옴표를 사용한 직접 인용이 아니다. 한 응답에 여러 주제가 있으므로 범주별 건수를 합산하지 않는다.

| 주제 | 원본 응답 근거와 해석 |
| --- | --- |
| 주요 긍정 평가 | R01은 이상 여부와 기술자료·점검 방법을 함께 확인하고 진단 과정이 기록되는 점을 유용하게 봤다. R02는 이상 원인 검토부터 점검·조치까지의 단계적 제안에 업무 활용 가능성을 느꼈다. R05는 진행 속도, R06은 PC의 수치 가독성을 긍정적으로 적었다. R04의 짧은 ‘예지보전 관련’ 응답은 명확한 긍정 평가로 확대 해석하지 않았다. |
| 사용법·용어·설명 보강 | R01, R04, R05의 3건은 처음 쓰는 사람의 용어 이해, 진행 방법, 화면 설명 부족을 언급했다. |
| 화면 구성·직관성 | R01, R03, R06의 3건은 각각 전체 화면 구성, 결과 탐색, 모바일 직관성을 지적했다. R03은 판정을 찾기 위해 스크롤해야 한다고 적었고, 결과를 위에 두며 데이터값은 원하는 사용자에게만 보이게 하자고 제안했다. |
| 모바일 사용성 | R06 1건은 PC 수치 표시는 편하나 모바일 화면은 덜 직관적이라고 구분했다. 모바일 설비 이력 ‘부분완료’도 3건/6건으로 다른 모바일 과업보다 1건 많다. 다만 부분완료의 구체 원인은 설문만으로 특정할 수 없다. |
| 현장 데이터 검증·연계 | R01은 실제 제조현장 데이터 검증을, R02는 현장 센서·설비 데이터 연계와 다양한 설비 적용을 제안했다. 두 응답을 현재 기능 검증 근거로 사용하지 않았다. |
| 데이터·모델 확대 | R02 1건은 다양한 설비·운전조건에서 판단할 수 있도록 학습 데이터 확대와 모델 성능 고도화를 요청했다. |

R03은 자유 의견에서 개인적으로 사용 의사가 없다고 적었으나, 별도의 재사용·추천 선택 문항에는 ‘잘 모르겠음’을 선택했다. 서로 다른 질문의 응답을 하나로 바꾸지 않았다.

### 8. 미반영 사항 및 향후 개선 방향

| ID | 미반영 사항 | 후속 확인 방향 |
| --- | --- | --- |
| FB-005 | 다양한 설비·운전조건의 데이터와 모델 평가 확대 | 신규 베어링과 운전조건을 분리한 평가 자료 확보, 모델 성능·오류 유형 재측정 |
| FB-006 | 실제 제조현장 데이터 검증 | 현장 데이터의 품질·라벨·적용 조건을 정의하고 독립적인 성능 검증 수행 |
| FB-007 | 현장 센서·설비 데이터 연계 | 데이터 수집·동기화·권한·장애 처리 요구를 정의한 후 제한된 연계 시험 수행 |

현재 MVP는 저장된 Paderborn Measurement를 분석한다. 기존 시험 Measurement의 지표를 새로운 베어링이나 실제 공장의 일반화 성능으로 해석할 수 없다. 실시간 현장 센서 수집과 자동 설비 제어는 구현 기능이 아니다.

평가 한계는 익명 유효 응답 6건의 소규모 표본, 식별정보 미수집으로 인한 중복 응답 및 고유 참여자 5명 이상 여부 확인 불가, 과업 결과의 자가 보고, 일부 테스트 환경·서비스 버전 정보 부재, 개선 후 재설문 미실시, 현장 적용 성능 미검증이다. 특히 모바일 이력 과업의 부분완료 원인은 추가 관찰 없이는 알 수 없다.

### 9. 종합 평가

사용자들은 이상 판정과 함께 기술자료·점검 방법·진단 과정을 볼 수 있다는 점과 단계적 점검 제안의 활용 가능성을 언급했다. 반면 진단 방법과 용어 설명 부족, 판정 결과를 찾는 탐색 부담, 모바일 화면의 직관성 문제가 확인됐다. 전체 만족도는 **3.33/5점**, 재사용·추천 의향 ‘예’는 **3건/6건(50.0%)**이었다.

이 의견을 바탕으로 사용 안내와 결과 표현을 보강하고, PC는 Agent Office 중심 구성을 유지하면서 모바일에는 결과 중심 요약과 선택형 상세 정보를 적용했다. 코드·테스트·화면 확인으로 구현과 기본 표시를 검증했지만, 사용자의 실제 이해도 또는 만족도가 높아졌는지는 아직 검증하지 못했다. 후속 평가는 개선 화면의 재사용성 시험과 현장 데이터·모델 일반화 검증을 별도로 수행해야 한다.
