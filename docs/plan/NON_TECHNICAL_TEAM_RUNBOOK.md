# 쉬운 실행·테스트·개선 운영 가이드

이 문서는 코드를 모르는 팀원이 AI Smart Factory Agent Office를 직접 실행하고,
정해진 시나리오를 테스트하고, 문제를 기록하고, 개선 후 다시 확인하기 위한 안내서다.
목표는 개발자가 아닌 사람도 같은 결과를 재현할 수 있게 하는 것이다.

## 1. 먼저 이해할 것

이 프로젝트는 공장 설비를 직접 제어하지 않는다.

```text
Measurement 선택
→ 센서 데이터 분석
→ 이상 여부 판단
→ 기술문서 근거 검색
→ 진단 후보와 점검계획 제시
→ 필요하면 사람에게 질문
→ 최종 보고서
```

화면에 보이는 상태는 장식용 애니메이션이 아니라 서버에서 실제로 진행된 작업 기록이다.
따라서 화면이 멈추면 “기다리면 된다”고 가정하지 말고, 마지막 상태를 기록해야 한다.

## 2. 용어를 쉬운 말로 바꾸기

| 개발 문서에서 만나는 용어 | 이 프로젝트에서의 쉬운 뜻 |
|---|---|
| Backend | 데이터를 처리하는 서버 프로그램 |
| Frontend | 사용자가 보는 웹 화면 |
| Agent | 여러 작업을 순서대로 수행하는 AI 프로그램 |
| Workflow | AI 작업이 진행되는 순서 |
| Measurement | 분석할 센서 측정 데이터 한 건 |
| Evidence / Citation | 답변을 뒷받침하는 문서 근거와 출처 표시 |
| HITL | AI가 사람에게 확인을 요청하는 과정 |
| resume | 멈췄던 작업을 이어서 진행하는 것 |
| Readiness | 실행에 필요한 파일과 저장소가 준비되었는지 확인하는 상태 |
| SSE | 서버의 진행 상황을 화면에 실시간으로 보내는 연결 |
| Regression test | 수정 후 기존 기능까지 다시 확인하는 전체 재시험 |
| P0 | 긴급 문제: 즉시 중단하거나 바로 고쳐야 하는 문제 |
| P1 | 핵심 기능 문제: 다음 테스트 전에 고쳐야 하는 문제 |
| P2 | 일반 개선 문제 |
| P3 | 있으면 좋은 개선 |

## 3. 팀 업무분장

| 역할 | 담당 업무 | 성공 기준 |
|---|---|---|
| 1. 실행·환경 담당 | 서버와 웹 화면을 켜고 접속 확인 | 브라우저에서 화면이 열림 |
| 2. 시나리오·기록 담당 | 정상/이상/사람 확인 시나리오 실행 및 결과 기록 | 다른 사람이 같은 테스트를 다시 실행 가능 |
| 3. 근거 검토 담당 | 검색 문서·출처·페이지 확인 | 답변이 실제 문서에 존재 |
| 4. 사용자 경험 담당 | 비전공자가 화면과 결과를 이해하는지 확인 | 도움 없이 과업 완료 가능 |
| 5. 개발·수정 담당 | 긴급 문제·핵심 기능 문제 수정과 전체 재시험 | 수정 전후 테스트 결과 비교 |

5명이라면 한 사람당 한 역할을 맡는다. 사람이 5명보다 적으면 실행·환경과 기록을
합치거나, 근거 검토와 사용자 경험을 합칠 수 있다. 테스트를 수행한 사람과 결과를
최종 승인하는 사람은 가능하면 분리한다.

## 4. 최초 1회 준비

### 3.1 필요한 프로그램

- macOS 또는 Windows 컴퓨터
- Python 3.11 이상
- Node.js 20 이상
- VS Code 또는 메모장
- Chrome/Edge 브라우저

이미 준비된 프로젝트 폴더를 사용한다. 데이터셋과 모델을 다시 다운로드하지 않는다.

### 3.2 폴더 열기

터미널을 열고 아래 명령을 한 줄씩 실행한다.

```bash
cd AI_Smart_Factory_Agent_Office
```

경로가 다르면 프로젝트 폴더를 Finder에서 터미널 창으로 끌어 놓아 경로를 확인한다.

### 3.3 환경 확인

```bash
backend/.venv/bin/python scripts/verify_setup.py
```

정상 결과는 마지막에 `"status": "pass"`와 readiness `ready`가 표시되는 것이다.

## 5. 매번 실행하는 방법

터미널 창을 두 개 사용한다.

### 창 A: 서버 프로그램

```bash
cd AI_Smart_Factory_Agent_Office
backend/.venv/bin/uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

다음 문구가 보이면 성공이다.

```text
Application startup complete
```

### 창 B: 웹 화면

```bash
cd AI_Smart_Factory_Agent_Office/frontend
npm run dev
```

브라우저에서 <http://localhost:3000>을 연다.

### 종료

각 터미널에서 `Ctrl+C`를 한 번 누른다. 컴퓨터를 강제로 종료하지 않는다.

## 6. 초보자용 테스트 순서

### 테스트 A: 정상 Measurement

1. 화면의 Measurement 선택에서 `paderborn:K001:N09_M07_F10:01` 선택
2. `AI 진단 시작` 클릭
3. 상태가 `COMPLETED`가 될 때까지 기다림
4. 최종 보고서에서 정상 판단과 버전을 확인

기대 결과: RAG 진단 단계 없이 정상 보고서가 생성된다.

### 테스트 B: 이상 Measurement

1. `paderborn:KA01:N09_M07_F10:01` 선택
2. `AI 진단 시작` 클릭
3. Agent Office에서 ML 이상탐지 → 근거검색 → 진단 → 점검계획 순서 확인
4. Evidence 카드의 문서명과 페이지/섹션을 클릭하거나 기록

기대 결과: 확정적인 안전 판정이 아니라 근거가 연결된 진단 후보와 권고조치가 보인다.

### 테스트 C: 사람 확인 요청

1. 사람 확인 또는 추가 정보 요청 상태가 될 때까지 이상 시나리오 실행
2. 사람이 제공할 수 있는 관찰 내용을 입력
3. 같은 작업 번호(`run_id`)가 유지되는지 확인
4. Resume 후 최종 보고서 확인

기대 결과: 새로 시작되지 않고 멈췄던 작업이 이어지며, 사람이 입력한 내용이 별도 출처로 표시된다.

### 테스트 D: 새로고침/재접속

1. 실행 중 브라우저 새로고침
2. 같은 run 화면으로 돌아오기
3. 이벤트가 중복되거나 순서가 뒤섞이지 않는지 확인

## 7. 테스트 기록 양식

아래 내용을 복사해 이슈 하나마다 작성한다.

```text
[테스트 ID]
실행 날짜/시간:
실행자:
시나리오: 정상 / 이상 / 사람 확인 / 새로고침 / 문서 검색
선택한 Measurement:
실행 단계:
기대한 결과:
실제 결과:
성공 여부: PASS / FAIL
작업 번호(run_id):
화면 문구 또는 오류:
스크린샷 파일명:
다시 실행했을 때 같은 문제가 발생했나: YES / NO
```

## 8. 문제의 긴급도

| 등급 | 의미 | 예시 | 처리 |
|---|---|---|---|
| P0(긴급) | 실행 불가 또는 안전상 오해 가능 | 서버가 시작되지 않음, 가짜 근거 표시 | 즉시 중지·개발자에게 전달 |
| P1(핵심 기능) | 중요한 시나리오 실패 | 이상 분석 미완료, 사람 입력 후 작업 재개 실패 | 다음 테스트 전 수정 |
| P2(일반 개선) | 기능은 되지만 불편함 | 문구가 어려움, 카드가 겹침 | 개선 목록에 등록 |
| P3(낮은 우선순위) | 있으면 좋은 개선 | 색상·간격·문구 다듬기 | 일정에 따라 처리 |

## 9. 문제 원인 찾기 순서

### 화면이 열리지 않음

1. 서버 창에 `Application startup complete`가 있는지 확인
2. `http://127.0.0.1:8000/api/v1/health`를 브라우저에서 열기
3. `status: ok`가 아니면 서버 창의 마지막 오류를 기록
4. 웹 화면 창에서 `npm run dev`가 실행 중인지 확인
5. 그래도 안 되면 두 창을 종료 후 다시 실행

### 실행 준비 상태가 `ready`가 아님

```bash
backend/.venv/bin/python scripts/verify_setup.py
```

출력에서 `ready: false`인 항목 하나만 기록한다. 데이터셋·모델·Knowledge Pack을 임의로 삭제하거나 다시 만들지 않는다.

### AI 작업이 멈춤

1. 화면의 마지막 작업 단계와 작업 번호 기록
2. 서버 창의 마지막 20줄 복사
3. 60초 이상 변화가 없으면 새로고침
4. 같은 run_id가 복구되는지 확인
5. 반복되면 P1로 등록

### 문서 검색 답변이 이상함

1. 질문 문장과 근거 출처 표시를 함께 복사
2. 해당 문서의 페이지/섹션에 실제 주장이 있는지 확인
3. 문서에 없으면 “근거 없음”으로 기록
4. 모델이 확정적으로 말했으면 P0 또는 P1로 분류

### 무엇을 고치지 말아야 하는가

- 테스트 중 데이터셋 원본 삭제
- `artifacts/` 아래 DB·모델·Vector Store 삭제
- 오류를 숨기기 위해 화면 문구만 변경
- 근거가 없는데 답변을 맞는 것으로 표시
- 실제 설비 제어를 연결

## 10. 개선 작업 흐름

```text
문제 재현
→ 테스트 기록 작성
→ 등급 결정
→ 수정 범위 합의
→ 수정
→ 동일 테스트 재실행
→ 전체 회귀 테스트
→ 결과 승인
```

수정 후 최소한 아래 명령을 다시 실행한다.

```bash
backend/.venv/bin/pytest -q
cd frontend && npm test && npm run build
```
